# Ratelline 제품 개선안 — 2026-10-06

상태: 승인된 범위의 구현과 자동 검증·독립 리뷰가 완료됨. 네이티브 실클릭·다중 모니터는 검증 한계로 남으며 사용자 최종 검수는 별도다. 이 문서는 출시 승인을 뜻하지 않는다.

## 목표와 유지할 가치

Ratelline을 열면 어떤 실행을 확인해야 하는지, 결과가 언제 확인된 것인지, 어느 계정과 프로젝트의 실행인지 바로 이해할 수 있게 한다. 개인 컴퓨터에서 실행되는 조회 전용 메뉴 막대·시스템 트레이 배포 모니터라는 핵심을 유지한다.

기존 서비스 연동, CLI 계정 분리, 프로젝트 선택, 표시 범위 상속, 독립적인 알림 규칙, 실행 숨기기와 되돌리기, 다국어, 이력 조회를 유지한다. 기존 작업 트리의 변경과 사용자 설정도 보존한다.

- 전체 브라우저 118개 중 117개가 통과했다. 변경 전 24시간 제한 문구를 기대하던 테스트를 갱신한 뒤 영향받는 16개가 모두 통과해 미해결 브라우저 실패는 없다. 네이티브 최종 리뷰·격리 실행 확인과 상태바 실클릭 검증 한계는 [QA 기록](qa-2026-10-06.md)에 구분한다.

## 1. 조회 상태를 정확하게 표현하기

실행의 상태와 조회의 상태를 별도로 다룬다. 예를 들어 배포는 마지막 확인 당시 실행 중이었지만, 현재는 조회 실패로 그 이후 상태를 모를 수 있다.

- 대상 식별자 `(provider, connectionId, targetId)`별 마지막 시도, 마지막 완전 성공, 현재 조회 결과를 메모리 스냅샷에 추가한다.
- 최근 목록 조회와 진행 중 조회의 결과를 합쳐 성공·부분 조회·실패를 판단한다. 이력 더보기 성공이 현재 모니터링 실패를 해소하지 않게 한다.
- 오래됨은 마지막 성공 시각과 조회 주기를 기준으로 판단하며, 재조회 중에도 이전 성공 시각을 보존한다.
- 기존 IPC 필드의 의미를 갑자기 바꾸지 않고 상태 필드를 추가한다. 새 정보가 없는 스냅샷은 미확인으로 처리한다. 사용자 설정 파일에는 새 마이그레이션을 요구하지 않는다.
- 전체·서비스·계정 화면의 요약은 현재 표시 대상의 상태를 집계한다. 일부 실패를 전체 정상으로 표현하지 않는다.
- 오랫동안 진행 중인 실행을 조용히 없애는 대신, 조회 기간과 표시 범위 안에서 마지막 관측 상태와 경과 시간을 설명한다. 데이터가 오래됐다는 이유로 배포 실패를 추정하지 않는다.
- 앱이 다시 활성화되거나 온라인으로 돌아왔을 때 오래된 결과를 재조회한다. 백엔드의 대기 중 조회를 깨우는 신호와 기존 중복 방지 경로를 사용하고, 반복 이벤트는 합친다. 숨겨진 창에서도 주기 조회는 계속한다.

완료 기준: 두 프로젝트 중 하나만 성공하거나 일부 행만 반환돼도 각 프로젝트의 상태와 시각이 정확하다. 복구는 해당 대상의 상태만 해소한다. 복귀 이벤트와 수동 새로고침이 겹쳐도 동일 조회가 중복 실행되지 않는다. 네이티브 절전 복귀는 실제 실행 근거가 있는 플랫폼만 검증했다고 기록한다.

## 2. 확인할 실행이 먼저 보이는 대시보드와 메뉴 막대

화면은 다음 순서로 구성한다.

1. 제목, 새로고침, 현재 조회 상태와 마지막 성공 시각.
2. 진행 중·실패·상태 미확인·최근 종료 수와 해당 목록으로 좁히는 상태 필터.
3. 검색·계정·기간과 현재 표시 범위.
4. 실행 목록과 선택한 실행의 상세 패널.

실패 수는 선택한 조회 기간의 실패 실행 수다. 서비스 장애 수 또는 미해결 사고 수로 표현하지 않는다. 배포 실패와 연결·조회 실패는 문구와 표시 위치를 구분한다.

- 실행 행에 서비스, 프로젝트, 브랜치, 워크플로, 연결 계정의 맥락을 필요한 만큼 표시한다.
- 기존의 외부 서비스 열기를 유지하면서 별도 상세 보기를 제공한다. 상세에는 이미 수집한 상태·실행자·시작/종료 시각·서비스가 제공한 실행 갱신 시각과 원본 열기, 숨기기·되돌리기를 배치한다. 수집하지 않은 로그나 원인은 만들어내지 않는다.
- 상태 필터는 화면 탐색 상태로 다루며 저장된 표시 범위나 알림 규칙을 바꾸지 않는다.
- 메뉴 막대에도 같은 상태 판정과 최신성 표시를 적용한다. 빠른 확인에 맞는 밀도를 유지하고 대시보드로 이어지게 한다.
- 까마귀 브랜드와 차분한 어두운 화면을 유지하되, 글자 위계·행 간격·대비·선택 표시를 정비한다. 실패나 복구 상태를 색만으로 전달하지 않는다.
- 첫 연결 전, 선택 프로젝트 없음, 필터 결과 없음, 부분 조회, 오래된 결과를 각각 설명한다.

완료 기준: 키보드로 필터·상세 열기·닫기·원본 열기를 사용할 수 있고 상세를 닫으면 원래 실행으로 포커스가 돌아간다. 1080px, 720px, 360px 및 420px 메뉴 막대에서 가로 넘침이 없고, 720×520 화면에서 핵심 상태와 첫 실행 또는 다음 설정 행동을 찾을 수 있다. 한국어·영어·일본어·중국어 간체가 같은 정보를 제공한다.

## 3. 연결부터 첫 조회까지의 완료 상태 보여주기

현재의 서비스·계정·프로젝트 설정 흐름을 다듬고 마지막에 첫 조회 결과를 연결한다.

- 서비스별로 도구 준비, 계정 확인, 프로젝트 선택, 첫 조회 완료를 구분해 현재 해야 할 행동을 보여준다.
- 기존 계정은 계정 정체성과 선택 프로젝트·조회 상태를 우선 보여준다. 인증 관리와 진단 상세는 필요할 때 펼친다.
- 실패한 프로젝트나 계정에서 해당 설정으로 바로 이동하며 계정 선택을 보존한다.
- 서비스 안내에서는 직접 조회 범위와 안내 전용 기능을 명확히 한다. 문서의 명령 계약 검증을 실제 계정 검증으로 표현하지 않는다.

완료 기준: 첫 프로젝트를 선택한 뒤 저장 성공과 원격 조회 완료를 구분할 수 있다. 설치 누락·로그인 만료·권한 실패·프로젝트 없음에서 다음 행동이 명확하다. 별칭·추가 계정·표시 범위·알림 설정과 저장 실패 재시도가 유지된다.

## 4. 구현 구조와 검증

Tauri 2, React, TypeScript, Rust와 현재 CSS를 유지한다. 화면 개편에 맞춰 대시보드 상태 계산, 조회 상태 집계, 실행 행·상세, 문구를 역할별 모듈로 나눈다. 화면마다 중복된 상태 판정은 공유하되 서비스별 원본 상태와 예외는 보존한다.

구현 순서는 조회 상태 모델과 테스트 → 대시보드·상세·메뉴 막대 → 연결 흐름 → 문서·통합 검증이다. 단계마다 영향을 받는 테스트를 수행하고 마지막에 프로젝트 필수 검사를 수행한다.

- TypeScript: `pnpm check`, `pnpm test`, `pnpm build`, `pnpm test:e2e`.
- Rust (`src-tauri`): `cargo fmt --check`, `cargo test`, `cargo clippy --all-targets -- -D warnings`.
- 회귀 확인: 동일 프로젝트의 다중 계정, 표시 범위 상속, 부분 조회, 오래된 응답, 설정 저장 실패, 숨기기·되돌리기, 알림 중복 방지, 대용량 이력 검색·점진 표시.
- 구현자와 분리된 reviewer가 정확성·회귀·실패 경로·완료 조건을 검토하고 발견 사항을 수정·재검증한다.
- `DESIGN.md`, `CONTRACT.md`, 관련 README에 최종 동작과 실제 검증 범위를 반영한다.

이번 개선은 활동 이력이나 알림 재전송 정보를 새로 디스크에 저장하지 않는다. 재시작 간 오프라인 이력·알림 보장은 저장 정책이 필요한 후속 결정으로 남긴다. 외부 서비스의 배포 변경 기능이나 새로운 서비스 연동을 추가하지 않는다. push·릴리스·배포는 이 계획의 구현 완료에 포함하지 않는다.

구현·검증·독립 리뷰가 끝나면 변경과 남은 한계를 보고하고 사용자 최종 검수를 받는다.
