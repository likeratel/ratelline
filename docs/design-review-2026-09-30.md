## 제품 이해와 기준

개발자가 작업 중 잠깐 상태바를 열어 자신의 배포 상태를 확인하는 로컬 조회 전용 앱이다. 대시보드는 상세 이력·연결·표시 설정을 위한 보조 화면이다. 따라서 우선순위는 상태 식별 속도, 조회 결과의 신뢰성, 첫 연결 성공, 반복 사용 시 낮은 조작 비용이다. 일반 분석 대시보드처럼 숫자 카드나 서비스 수를 크게 보여주는 것이 목적은 아니다.

유지할 점: 패널/대시보드 분리, 동봉 플랫폼 로고, 36px 일반·28px 패널 컨트롤, 고정 대화상자 헤더/푸터, 한 곳의 본문 스크롤, 읽기 전용·기존 인증 안내, 일부 조회/미확인 상태의 구분.

## 우선 개선 사항

### 1. 높음 — 연결 화면에서 실행할 작업이 첫 화면 밖으로 밀림

**관찰:** 기본 1080×780 가상 화면과 현재 네이티브 대시보드에서 19개 플랫폼 카탈로그와 3단계 안내가 연결 본문의 대부분을 차지한다. 계정 선택·연결 확인·감시 대상은 아래로 스크롤해야 나타나지만 저장 버튼은 먼저 보인다.

**영향:** 처음 사용하는 사람은 플랫폼을 선택한 다음 무엇을 해야 하는지 찾게 되고, 이미 연결한 사람도 매번 같은 안내를 지나간다. 패딩 부족보다 정보 순서의 문제다.

**권장:** 연결된 서비스와 현재 계정/대상을 먼저 보여주고 전체 카탈로그는 ‘서비스 추가’에서 연다. 선택 후 해당 서비스 설정으로 명확하게 전환한다. 연결 완료 계정의 긴 안내는 접고, 인증이 없을 때 준비 단계만 펼친다. 중첩 스크롤은 다시 도입하지 않는다.

**완료 기준:** 기본 창에서 선택된 서비스·계정·다음 행동이 스크롤 없이 보이며, 720×520에서도 다음 행동에 쉽게 도달한다.

근거: [Connections.tsx](../src/components/Connections.tsx#L339), [connections.css](../src/styles/connections.css#L49), 기존 `artifacts/ratelline-dialog-guide-full.png`, 실제 앱 첫 연결 화면.

### 2. 높음 — 상태바의 상태 표시가 플랫폼 로고에 비해 너무 작음

**관찰:** 플랫폼 로고는 22px, 성공·실패·진행 표시는 모서리의 10px 아이콘이다. 완료 목록에는 시각적인 상태 문구가 없다. 접근성 이름에는 상태가 있어 스크린리더 정보가 아예 없는 문제는 아니다.

**영향:** 앱의 핵심 질문인 ‘성공했나, 실패했나’를 플랫폼보다 늦게 읽는다. 특히 실패와 건너뜀을 빠르게 구분하기 어렵다.

**권장:** 로고는 유지하면서 상태 아이콘을 독립된 14–16px 자리로 옮기거나 짧은 상태 문구를 병기한다. 모든 실패를 무조건 위로 올리기보다는 최신순을 유지하면서 실패·대기를 분명히 표시한다.

**완료 기준:** 420px 패널에서 hover 없이 성공/실패/진행/대기를 구분할 수 있고 긴 실행명도 읽을 공간을 유지한다.

근거: [TrayPanel.tsx](../src/components/TrayPanel.tsx#L56), `artifacts/ratelline-panel.png`.

### 3. 높음 — 같은 창에서 저장 적용 시점이 다름

**확인된 동작:** 계정 추가·제거는 bridge 호출로 즉시 저장된다. 감시 대상 선택은 창 하단 ‘설정 저장’을 눌러야 반영된다. 계정 제거 버튼은 휴지통 아이콘이며 확인/되돌리기 단계가 없다.

**영향:** ‘닫으면 이번 변경은 취소된다’는 사용자의 기대와 충돌한다. 배포나 자격 증명을 삭제하지는 않지만 계정 연결과 감시 대상 구성을 잃을 수 있다. 실제 사용자 계정을 제거해 재현하지 않고 호출 경로로 확인했다.

**권장:** 계정 관리를 별도 영역으로 분리하고 ‘즉시 적용’을 명시한다. 제거 시 연결 이름과 제거될 감시 대상 수를 확인하거나 실행 취소를 제공한다. 하단 버튼은 적용 범위가 드러나는 ‘감시 대상 저장’으로 바꾼다.

**완료 기준:** 계정 제거 영향이 실행 전 보이며, 저장 버튼이 담당하는 변경 범위를 설명할 수 있다.

근거: [AccountPicker.tsx](../src/components/AccountPicker.tsx#L95), [Connections.tsx](../src/components/Connections.tsx#L118), [Connections.tsx](../src/components/Connections.tsx#L144).

### 4. 중간 — 미지원 플랫폼이 지원 플랫폼과 같은 모습으로 나열됨

**관찰:** Expo/EAS, Cloudflare, Firebase, Supabase, fastlane도 같은 버튼 스타일이며, 선택 후에야 제한 안내를 읽을 수 있다. 소스에서 미지원 상태를 성공으로 표시하지는 않는다.

**영향:** 처음 보는 사용자는 로고 목록을 지원 목록으로 해석하기 쉽다.

**권장:** ‘직접 연결 가능’과 ‘CI를 통해 확인/직접 연결 미지원’을 구분하고 서비스 카드에서 상태를 표시한다. ‘준비 중’은 실제 구현 계획이 있을 때만 사용한다.

**완료 기준:** 누르기 전에 직접 연결 가능 여부를 알 수 있고, 미지원 항목은 대체 경로를 설명한다.

근거: [Connections.tsx](../src/components/Connections.tsx#L354), [platformDetails.ts](../src/platformDetails.ts).

### 5. 중간 — 상태바의 빈 목록이 필터 결과인지 알기 어려움

**확인된 동작:** 패널은 대시보드의 실행자 범위와 별도의 서비스/대상 표시 설정을 적용한다. 빈 섹션은 공통 문구 ‘해당하는 실행이 없습니다’를 사용하며 패널에 현재 적용 범위가 보이지 않는다.

**영향:** 실제로 실행이 없는 경우와 ‘내 실행만’ 또는 숨긴 대상 때문에 제외된 경우를 혼동한다. 조회 전용 모니터의 신뢰를 떨어뜨릴 수 있다.

**권장:** 조작 요소를 늘리기보다 ‘내 실행 · 3개 대상’ 같은 짧은 범위 표시를 넣는다. 빈 결과에서는 필터 조건과 표시 설정으로 이동할 경로를 제공한다. 조회 오류는 기존처럼 별도로 유지한다.

**완료 기준:** 사용자가 패널만 보고 현재 범위와 빈 결과의 가능한 이유를 이해한다.

근거: [domain.ts](../src/domain.ts#L287), [TrayPanel.tsx](../src/components/TrayPanel.tsx#L113), [PanelPreferences.tsx](../src/components/PanelPreferences.tsx#L47).

### 6. 중간 — 작은 보조 글자와 일부 대비 미달

**측정:** 지정 CSS 색상으로 계산한 패널 빈 안내 `#737b86` / 배경 `#111214` 대비는 약 4.38:1, footer `#747c88`는 약 4.45:1이다. 일반 텍스트 AA 기준 4.5:1에 못 미친다. 안티앨리어싱 픽셀을 측정한 것이 아니라 지정 전경/배경색 계산이다. 대시보드 시간은 9px, 상태/메타는 10px이며 DESIGN.md의 본문 13px·도움말 12px 규칙과 실제 체계에 간극이 있다. 작은 글자 크기 자체를 WCAG 실패라고 단정하지 않는다.

**권장:** 의미 있는 메타/도움말을 12px 중심으로 정리하고, 패널의 의도된 압축 크기는 별도 토큰으로 정의한다. 빈 상태·갱신 시각의 대비를 4.5 이상, 가능하면 여유 있게 올린다.

**완료 기준:** 활성 정보 텍스트 대비 기준 충족, 크기 토큰의 예외가 문서화되고 임의의 9/10/11px 사용이 줄어든다.

근거: [panel.css](../src/styles/panel.css#L201), [App.css](../src/App.css#L478), [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

## 제품 방향 제안 — 취향/우선순위에 따른 선택

대시보드는 현재 큰 숫자 카드, 필터, 도움말, 진행 중 빈 상태를 지나야 최근 배포가 나온다. 실제 진행 항목이 없는 화면에서는 ‘0’ 카드와 82px 빈 영역이 같은 사실을 반복한다. 진행 중 0건일 때는 한 줄로 축약하고 최근 실행을 위로 당기는 편이 이 제품에 적합하다. 이는 기능 결함이나 접근성 위반이 아니라 화면 밀도와 정보 우선순위에 대한 제안이다.

다크 테마·모노톤 로고·현재 글꼴을 바꾸는 전면 리브랜딩은 우선하지 않는다. 연결 흐름과 상태 식별을 먼저 개선한 뒤 목록 밀도와 여백을 조정하는 순서가 효과적이다.

## 검증 범위와 한계

- 현재 macOS 앱의 상태창 접근성 트리, 대시보드, 연결 대화상자 첫 화면을 직접 확인했다. 대시보드 진입·연결 창 열기·Escape 닫기를 수행했다.
- 저장된 합성 데이터 스크린샷 4종(대시보드, 연결, 상태창, 좁은 표시 설정)을 확인했다. 좁은 화면은 기존 산출물이며 이번에 새로 촬영하거나 창 크기를 변경한 결과가 아니다.
- 컴포넌트·CSS·상태 필터·저장 호출 경로를 읽고 대비를 계산했다. 삭제/로그인/설정 저장 등 실제 데이터 변경은 수행하지 않았다.
- 이번 리뷰에서는 빌드·E2E 전체 재실행, Windows UI, VoiceOver 전체 탐색, 확대/고대비 모드, 간헐적 외부 클릭 문제의 재현을 수행하지 않았다. 해당 항목의 통과를 주장하지 않는다.
- 코드 수정·커밋·푸시는 하지 않았다. 제품 변경을 막는 외부 블로커는 없으며, 위 결과는 다음 구현의 우선순위 자료다.

## 개선 구현 — 2026-09-30

사용자 승인 후 위 6개 개선과 빈 진행 영역 축소를 반영했다. 현재 계정·연결 동작을 먼저 배치하고 카탈로그와 안내를 접었다. 서비스 선택은 카탈로그를 닫고 설정으로 초점을 옮긴다. 상태바에는 독립 상태 아이콘·실행자 범위·표시 대상 수·조건별 빈 안내를 추가했다. 계정 제거는 계정 ID에 묶인 확인 단계를 거치며, 감시 대상 저장과 즉시 적용되는 계정 작업을 구분한다. 보조 문구 크기와 대비를 개선했다.

독립 리뷰에서 계정 전환 중 제거 확인 유지, 선택 후 카탈로그 유지, 시각 순서와 키보드 순서 불일치, AWS 무계정 설정의 비활성 버튼 포커스를 발견해 수정했다. `pnpm check`, `pnpm test` 16개, 브라우저 E2E 24개(전체 23개 및 AWS 무계정 회귀 추가 후 영향받은 테스트 재실행)를 통과했다. 가상 데이터 스크린샷으로 기본·720×520 연결 창과 420×540 상태바를 확인했다. 실제 계정 삭제나 로그인은 수행하지 않았다.

최종 독립 재검토에서 미해결 발견 사항은 없었다. `pnpm tauri build --bundles app`으로 최종 앱을 빌드하고 11:27 KST에 새 프로세스로 재시작했다. 네이티브 상태바의 표시 범위, 대시보드의 축소된 진행 중 빈 상태, 연결 창의 계정·조회 버튼 우선 배치와 실제 DOM 안내, Escape 닫기를 확인했다. Windows·VoiceOver 전체 탐색과 간헐적 외부 클릭 문제는 이번 검증 범위에 포함하지 않았다.

## 사용자 피드백 반영

사용자가 이전 연결 화면을 선호하여 서비스 카탈로그와 연결 안내를 펼친 기존 구성을 복원했다. 계정 제거 확인과 감시 대상 저장 구분은 유지했다. 사이드바의 로컬 CLI 인증 안내 문구를 제거했다. 상태바 정렬·우선순위는 변경하지 않았다. `pnpm check`, 브라우저 E2E 22개가 통과했다.
